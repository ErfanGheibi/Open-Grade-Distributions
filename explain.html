Methodology

How the numbers are calculated

Grade categories

UNSW's disclosure log reports 20 grade codes per course offering. We grouped them using UNSW's own "Grade Code / Grade Description" legend (printed on page 1 of the disclosure log PDF), not by guessing what a code probably means:

GroupCodesMeaning
FailFL, UF, AF, NFFail, Unsatisfactory Fail, Absent Fail, Fail/Not Successful/Discontinued
Standard pass scalePS, CR, DN, HDPass, Credit, Distinction, High Distinction
WithdrawalAW, PWAcademic Withdrawal, Permitted Withdrawal
Competency scaleCN, CO, CM, SYNot Yet Competent, Competent, Competent with Merit, Successful/Satisfactory
Other / in-progressEF, EC, EM, AS, PE, NCEnrolment Continuing (×2), Excluded (Misconduct), Audited, Professional Experience, Not Completed

Normalized rates

The Fail %, PS %, CR %, DN % and HD % columns are normalized against withdrawals only, as requested: a withdrawal isn't really an academic outcome, so we don't let it dilute the fail/pass percentages. Concretely, for each course offering:

Base = 100% − (AW% + PW%) Fail_norm = (FL% + UF% + AF% + NF%) / Base × 100 PS_norm = PS% / Base × 100 CR_norm = CR% / Base × 100 DN_norm = DN% / Base × 100 HD_norm = HD% / Base × 100

We deliberately don't also strip out the "other" or competency-scale categories from the base — only withdrawals are excluded. This means a course with an unusually large Enrolment Continuing (EF/EC) share — common in multi-term thesis courses — will show suppressed Fail/Pass percentages that term. We flag any offering where "other" grades exceed 15% with a note, but don't hide it.

Non-standard (competency) grading

A number of UNSW courses — mostly practicums, placements, and law/professional-practice electives — are graded Competent / Not Yet Competent / Competent with Merit rather than Fail through High Distinction. For these, the standard Fail/PS/CR/DN/HD columns would just show zeros, which is misleading rather than informative. We instead detect them (negligible standard fail+pass activity, but meaningful CN/CO/CM/SY activity) and mark the row "Non-standard grading" in the table, with a tooltip listing the actual grade breakdown.

Redacted rows

Some rows in UNSW's disclosure log are blacked out under GIPA sections 3(a) and 3(b) (their public-interest exemption clauses) — typically small classes, where individual students' results could otherwise be inferred. These rows are kept in the dataset (rather than deleted) so the ledger accurately reflects what was and wasn't disclosed, but every metric column is left blank and shown as "REDACTED BY UNIVERSITY" in the table.

The Ease/Hardness Index

There's no official measure of "how hard" a course is, so we built one. It rewards High Distinctions heavily, Distinctions moderately, Credits lightly, and penalises Fails one-for-one against High Distinctions — Passes are treated as neutral and don't move the score either way:

Index = HD_norm − Fail_norm + 0.5 × DN_norm + 0.25 × CR_norm

Higher Index = more High Distinctions relative to Fails = "easier" by this measure. Lower (more negative) = "harder". It's a deliberately simple, transparent heuristic — not a validated difficulty score — and it's — (blank) for redacted rows and non-standard-grading rows, since Fail/HD percentages aren't meaningful there. We'd genuinely welcome a better formula; this one is a reasonable starting point, not a claim of precision.

Term codes (T1–T3, S, H1–H6)

UNSW has used several different term-naming systems over the years covered by this data. We use three separate codes rather than squeezing them into one artificial scale:

  • T — a regular-length term: Semester 1/2, Term 1/2/3, or Trimester 1/2/3.
  • S — a Summer session. This gets its own code rather than being folded into T3: a course can run both a regular Term 3 and a separate Summer Term in the same year, and those are two different student cohorts with two different results, not one term counted twice.
  • H — a Hexamester (H1–H6): UNSW splits the year into six shorter sub-terms for a subset of flexible-delivery courses (mostly postgraduate). No course in this dataset mixes the Hexamester system with the Term/Summer system, so the two never need to line up against each other.

The number always comes directly from UNSW's own term text where one is given — e.g. "Hexamester 4" becomes H4, "Semester 1" becomes T1. Combined with the two-digit year, a course offering in Term 1 2024 is labelled 24T1; one in Hexamester 5 2023 is 23H5. The exact original term text (e.g. "Semester 2 Canberra") is still shown in full in the underlying CSV.

For the date-range filter and the chronological dashboard charts, each code maps to a fixed position within its year (H1–H6 map straight to 1–6; T1/T2/T3/S map to 1/3/5/6) so that terms are ordered correctly and — importantly — two genuinely different terms are never accidentally merged into one data point.

Cross-listed cohorts (same code, two student populations)

A number of course codes are cross-listed: the same code runs one cohort for Undergraduate students and a separate one for Postgraduate students in the same term, often with very different results (a 20-student undergraduate class next to a 1-student postgraduate one, for instance). These appear as separate rows in the table. The dashboard only ever charts one cohort at a time — whichever row you clicked — and tells you when a second cohort exists so you can switch to it, rather than silently averaging two different student populations into one misleading line.

Course code splitting

Each row's raw "Course" text (e.g. PSYC5001 Introduction to Psychology 1 065551 1 PGRD) is split into Course Code, Course Name, Course ID (the internal 6-digit UNSW class ID), and an Offering Seq number. That last single digit is almost always 1, occasionally 2 or 3 across the dataset — our best guess is that it's a sequence number distinguishing multiple offerings/sections of the same course in the same term, but UNSW's disclosure log doesn't document the field, so treat that interpretation as informed speculation rather than fact.
